# ViewTimer v1 技术方案：腾讯视频官网客户端版

> **⚠️ 实现期修订（2026-11-14，以 `../README.md` 的「实测结论」为准）**
> 本文第四节的「MediaRemote adapter 事件驱动」路线**已作废**。
>
> **2026-11-14 二次修订（重要，第一版修订说错了）**：
> - `MRMediaRemoteGetNowPlaying*` 确实被封（PID 返 0 / info 返 null，连自注册的进程都读不到）。
> - **但 `MRMediaRemoteSendCommand` 没有失效**。它只投递给「已注册 Now Playing」的 App，
>   且是异步 XPC —— 发送进程发完立刻退出会静默丢包。旧结论「返回 true 但空转」是踩了这个坑。
> - **腾讯视频不注册 Now Playing**，所以发 pause / toggle / play 全部无反应（实测音频持续 16 秒）。
>   因此 v1 仍必须走「激活 + 空格」，不能收敛成「只发 pause」。
>   v2 的 Edge 网页版则可以直接用 pause（Chromium 会注册）。
> - 另修正本文假设：暂停后音频设备**不会**立即释放（滞后约 8 秒）；空格有效，
>   但必须先确认客户端真的切到前台（全屏 Space 切换有动画）。
> - 「AX 直接按暂停控件」一级已从实现中移除（拿不到控件，且 8 秒窗口内无法判定成败）。

> **2026-11-15 三次修订（v1.2）**：本文第四 / 五节把「退出 App」「关浏览器标签」
> 描述成**失败才触发的兜底级**，且强调「绝不抢焦点」。该设计已废弃——用户勾选后
> 到点常常什么都没发生。现在两项是**勾选即执行的到点附加动作**：独立于播放状态 / 音频信号 / 前台判断，
> 统一在 `StopExecutor.finishAll` 里执行，顺序为「关标签 → 退出腾讯视频 → 复核 → 锁屏」。
> 代价（抢焦点、丢进度与页面状态）由用户勾选时显式承担，详见 `README.md`。

> **范围锁定**：主目标 Mac mini / macOS 15.8（Apple Silicon），播放源为**官网下载的腾讯视频 Mac 客户端 V2.190.x**（非 App Store 版）。
> **v1 只做客户端渠道**；Edge 网页版（v.qq.com）留到 v2。次要目标 Mac Pro / macOS 12.x 用同一份包验证，不单独适配。
> 本文是 v1 的开工方案，含架构、模块设计、降级链、Spike 清单、验收标准与 v2 预留接口。
> 日期：2026-11-14

## 一、范围与架构反转

用户确认先看客户端，这让 v1 的**架构变轻、但「播完当前」变难**：

| | v2 网页版方案（上一轮定案） | **v1 客户端版（本方案）** |
|---|---|---|
| 组件 | 菜单栏 App + Edge MV3 扩展 | **只有一个菜单栏 App** |
| 跨进程通信 | Native Messaging | **不需要** |
| 进度读取 | 扩展直读 `<video>.duration/currentTime`，高可靠 | 客户端黑盒，**需降级链** |
| 停止动作 | 扩展 `video.pause()`，不需焦点 | 系统暂停 / CGEvent 发键 / ⌘W 关标签 / 退出 App |
| 权限 | 辅助功能（App 侧） | 辅助功能（必需）+ 可选自动化 |
| 分发 | App + 扩展 Load unpacked | 单个 .app，Developer ID + 公证 |

**结论**：v1 是纯原生菜单栏 App，工程量和分发复杂度都低于 v2。但必须诚实划清能力边界——**「立即停止」稳，「播完当前」需要降级**，不要对 v1 承诺「自动精确判定本集结束」。

不过本方案找到一条比「填片长估算」更好的路（见第四节）：借客户端自带的「播完当前剧集」+ 监听播放停止事件，可把 v1 的「播完当前」从估算升级为**事件驱动**。

## 二、v1 能力边界（对外承诺口径）

| 功能 | v1 结论 | 实现 / 依据 |
|---|---|---|
| 定时器（预设 + 自定义 + 稍后提醒） | **稳** | 纯本地状态机，无系统依赖 |
| 到点立即停止播放 | **稳** | 暂停链：系统暂停 → 空格 → 媒体键；加上两个「勾选即执行」的到点附加动作：退出腾讯视频 / 关浏览器标签 |
| 到点锁屏（可开关） | **稳** | CGEvent 发 `Control+Command+Q`，或 `shortcuts run` 调「锁定屏幕」 |
| 全屏提醒 / 提前提示 / 提示音 | **稳** | 原生窗口，无权限依赖 |
| 「停止 + 锁屏」联动 | **稳，且是核心差异化** | 严格先暂停再锁屏（锁屏本身不中断播放） |
| 播完当前再停（事件驱动） | **可用，但有坑** | 监听 CoreAudio 静默 + 客户端进程退出。精度≈本集结束后 10~11 秒；**客户端开自动连播时失效**（下一集接上，音频不掉 0） |
| 播完当前再停（精确自动） | **不可行（已排除）** | QQLive 非 Electron/CEF（原生 `QLV*` framework 栈），无 CDP 调试端口可开 |
| 播完当前再停（估算兜底） | **稳** | 用户填本集剩余时长 + 最长等待上限 |
| 上 Mac App Store | **不可行** | 沙盒禁止辅助功能 API / 终止其他 App / 私有框架 |

**差异化定位**：原假设「腾讯视频官网客户端自带『定时关闭 / 播完当前剧集 / 播放完影片自动关机 / 定时关机』」——
**2026-11-14 实测推翻了这条**：在本机 QQLive 2.190.0 的二进制与全部资源里搜不到上述任何功能字样，
只找到「少儿守护」入口（`MainWindowChildGuardExtension`，主窗口 leading 区）。

> 待人工在客户端 UI 的「设置」里逐项确认（可能由服务端下发、不走本地字符串）。
> 若确认确实没有定时能力，则 v1 的价值不只是「停止方式与联动」，「定时」本身就是刚需。

即便客户端有定时，v1 的价值仍在于：

1. **停止 + 锁屏联动**（客户端是关机/退出，不是「只暂停 + 锁屏」）
2. **不关机只暂停**（睡前场景，不打断整机其他任务）
3. **全屏提醒 + 稍后再看 5 分钟**（客户端倒计时不会给人反应窗口）
4. 后续 v2 纳入网页版后的**跨渠道统一管理**

> 这一条必须让产品侧接受：v1 卖的是「停止方式与联动」，不是「定时能力」。

## 三、架构与状态机

```
┌──────────────────────────────────────────────────────────┐
│ ViewTimer.app（Swift / SwiftUI，LSUIElement 菜单栏 App）  │
│  非沙盒 · Developer ID + Hardened Runtime + 公证          │
│                                                          │
│  ┌────────────┐  ┌─────────────┐  ┌──────────────────┐  │
│  │ TimerEngine│→ │ StopExecutor│→ │ SystemActions    │  │
│  │ 状态机/倒计时│  │ 四级停止兜底 │  │ CGEvent/锁屏/退出 │  │
│  └────────────┘  └─────────────┘  └──────────────────┘  │
│         ↑                ↑                               │
│  ┌────────────┐  ┌─────────────────────────────────────┐ │
│  │ UI / 提醒  │  │ PlaybackEndMonitor（v1 关键）       │ │
│  │ 菜单栏+全屏│  │ adapter stream / NSWorkspace 通知  │ │
│  └────────────┘  │ / AXObserver / CDP（探索）          │ │
│                  └─────────────────────────────────────┘ │
│  ┌────────────────────────────────────────────────────┐  │
│  │ MediaRemoteBridge（可选，运行时 test 自检）        │  │
│  │ 打包 mediaremote-adapter.pl + framework + testcli │  │
│  └────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────┘
```

**状态机**

```
idle ──start──> running ──(提前 20s)──> warning ──确认/超时──> executing ──> done
                   │                        │                       │
                   ├─ cancel ──────────────┴───────────────────────┴──> idle
                   └─ snooze(+5min) ──> running

running 且 strategy=episode：
  等待 PlaybackEndMonitor 的「本集结束」事件
  ├ 收到事件 ──────────────────────────> executing
  └ 到达「最长等待上限」仍无事件 ───────> executing（降级，记日志）
```

**两条策略共用同一个 `executing` 序列**，差别只在触发条件，这样 v2 加网页渠道时只需替换触发器。

## 四、「播完当前再停」的 v1 降级链（按优先级）

这是 v1 唯一的技术难点。设计成四级，前两级可能把它从「估算」提升到「精确」：

**L0 · 借力事件驱动（首选，需 Spike 4 确认）**
腾讯视频官网客户端自带「定时关闭 / 播完当前剧集」。让用户去客户端开启该选项，我们的 App **不负责判定片尾，只负责监听"播放停止"事件**，然后执行锁屏 + 提醒。监听两路（任一触发即可）：

- `media-control stream`（adapter 实时推送）：监听 `payload.playing` 由 `true` → `false`，或 `bundleIdentifier` 消失；
- `NSWorkspace.didTerminateApplicationNotification`：若客户端「播完当前」的语义是退出 App，进程退出事件天然精确，且**完全不依赖 MediaRemote**。

> 这是本方案相对上一轮的关键改进：即使客户端不上报 `duration`/`elapsedTime`，只要能观测到「播放停止」这个状态变化，就能做到事件驱动的精确停止，而不是靠用户猜片长。

**L1 · CDP 精确读取（探索项，Spike 0，不承诺）**
若官网客户端是 Electron/CEF 且允许调试端口，可直接读页面内 `<video>` 的 `duration` / `currentTime`，与 v2 网页版同精度：

```bash
# 先彻底退出客户端（open -a 对已运行进程传参通常不生效）
osascript -e 'quit app "腾讯视频"'
"/Applications/腾讯视频.app/Contents/MacOS/腾讯视频" --remote-debugging-port=9222 &
curl -s http://127.0.0.1:9222/json/list
```
有 JSON 返回即可用 CDP `Runtime.evaluate` 读 `<video>`；腾讯可能已移除该能力，**不能作为承诺**。

**L2 · MediaRemote 进度读取（需 Spike 5 确认）**
`media-control get --now` 看 `duration` / `elapsedTime` / `uniqueIdentifier` 是否有值。Electron 类应用通常不上报，预期大概率为空；若意外有值，可直接算剩余时间并精确触发。

**L3 · 估算兜底（100% 可靠，永远保留）**
用户在菜单栏填「本集剩余约 N 分钟」+「最长等待上限 M 分钟」，到 `min(N, M)` 触发；同时任何时刻用户可手动「立即停止」。覆盖 DRM、改版、直播、试看等所有异常，也是 L0/L1/L2 全失败时的保底。

**产品呈现建议**：把 L0 做成默认的「推荐：先在腾讯视频里开启『播完当前剧集』」，L3 作为输入框常驻。UI 上明确标注「v1 为事件驱动 / 估算模式，精确自动检测将在 v2 网页版提供」，避免预期错位。

## 五、停止动作执行器（现行实现，五级）

> 本节已按 2026-11 实机结论重写。原设计的 `AX 直接按暂停控件` 一级**已删除**（腾讯视频是自绘 UI，
> 拿不到控件，且按下后无法安全判定成败）；`MediaRemoteBridge.send(.pause)` 收敛为第 1 级，
> 且只对「注册了 Now Playing」的 App 有效。

顺序不可乱，且每一步尽量验证是否真的停了（浏览器通道无法验证，见下）：

| 级 | 动作 | 生效范围 | 能否验证 |
|---|---|---|---|
| 1 | `MRMediaRemoteSendCommand(kMRPause)`（幂等） | 浏览器 / QuickTime / 音乐等注册了 Now Playing 的 App | 浏览器 ❌，原生播放器 ✅ |
| 2 | 激活客户端到前台（失败重试一次）→ 空格 | 腾讯视频 | ✅ CoreAudio 音频回落 |
| 3 | 媒体键 `NX_KEYTYPE_PLAY(16)` | 腾讯视频（焦点在输入框里时空格只会打出空格） | ✅ 同上 |
| 附加 a | ⌘W 关标签页（勾选即执行，主动激活运行中的浏览器） | 浏览器 | ❌ 无法复核 |
| 附加 b | `terminate()` / `forceTerminate()` 客户端（勾选即执行） | 腾讯视频 | ✅ 进程退出 |

关键约束（均为实测所得，不要凭直觉简化）：

- **第 1 级是幂等的**，所以可以无条件发；空格/媒体键都是 toggle，必须先确认在播。
- `MRMediaRemoteSendCommand` 是**异步 XPC**：返回 true 只代表请求入队。发完立刻退出进程会
  **静默丢包**（这正是早期误判「API 空转」的根因）。发完必须让进程再活约 1 秒。
- **v1.2 起附加 a 会主动抢焦点**（勾选即视为授权）：⌘W 只作用于前台窗口，
  必须 `activateAndWait()` 确认浏览器真的到前台再发键，否则会打偏。
  代价是用户正在用的窗口会被切走、且可能关掉一个无关标签；已在面板文案、全屏提醒与日志里明示。
  旧版「只在浏览器已在前台才动手、绝不抢焦点」的做法会导致勾了开关却不执行，已废弃。
- ⌘W 依赖**菜单项快捷键**（File > Close）：没有菜单栏的 App 不会响应，真实浏览器都有。

**锁屏**永远在停止动作之后：`CGEvent` 组合 `kVK_Control(0x3B)` + `kVK_Command(0x37)` + `kVK_ANSI_Q(0x0C)`；备选 `shortcuts run "锁定屏幕"`。再次强调：`Control+Command+Q` **响应即时且不中断后台音视频播放**，Edge/浏览器与客户端在锁屏后都可能继续播，所以「先暂停再锁屏」是硬约束。

## 六、权限、签名与分发

| 项目 | 要求 |
|---|---|
| 辅助功能 | **必需**：CGEvent 发键、AXUIElement。用 `AXIsProcessTrusted()` 检测并做引导页 |
| 自动化（Apple Events） | 仅当用 AppleScript 控制客户端时加 `com.apple.security.automation.apple-events`；主路径不依赖 |
| 屏幕录制 | 不需要 |
| 签名 | 非沙盒 + Developer ID + Hardened Runtime + 公证；**不上 Mac App Store** |
| library validation | 公证强制 Hardened Runtime，会阻止 `perl` 加载自定义 framework。**推荐**把 `MediaRemoteAdapter.framework` 用同一 Developer ID 签名；备选加 `com.apple.security.cs.disable-library-validation` |
| 打包细节 | `mediaremote-adapter.pl`、`MediaRemoteAdapter.framework`、`MediaRemoteAdapterTestClient` 放进 `Contents/Resources/`，**只打包不 link**；包内 framework / helper / dylib / 脚本逐个签名，否则公证返回 Invalid |
| 运行时自检 | 启动跑 `/usr/bin/perl <pl> <framework> <testcli> test`，退出码 0 才启用 MediaRemote 相关能力，否则自动降级到 L3 |
| 架构 | framework 为 x86_64 + arm64 通用二进制，Mac mini（arm64）与 Mac Pro（Intel）一份包；检查客户端是否需 Rosetta：`lipo -info "/Applications/腾讯视频.app/Contents/MacOS/腾讯视频"` |

## 八、Spike 清单（v1 优先级重排，1~2 天）

| # | 测什么 | 怎么做 | 通过标准 / 影响 |
|---|---|---|---|
| **0** | **客户端能否开 CDP 调试端口** | 彻底退出后带 `--remote-debugging-port=9222` 启动，`curl http://127.0.0.1:9222/json/list` | 有 JSON 返回 → **v1 也可能做到精确「播完当前」**，最高杠杆 |
| **1** | 客户端自带的「播完当前剧集」语义 | V2.190.x 设置 / 播放菜单逐项确认：是停止播放、退出 App、还是关机 | 决定 L0 走 `playing=false` 还是 NSWorkspace 退出监听 |
| **2** | Mac mini 15.8（arm64）上 adapter 是否工作 | `brew tap ungive/media-control && brew install media-control` → `media-control test` | 退出码 0；决定 L0/L2 与 `send pause` 是否可用 |
| **3** | 客户端是否上报 Now Playing | 播放时 `media-control get --now`，看 `bundleIdentifier` / `duration` / `elapsedTime` / `playing` | 至少有 `playing` 即可支撑 L0；有 `duration` 则 L2 成立 |
| **4** | adapter 的 `send` 支持哪些命令 | `media-control send pause`（或查 adapter 文档命令表），观察客户端是否暂停 | 支持 pause → 停止执行器第 1 级可用，避开媒体键 toggle 坑 |
| **5** | 停止动作有效性 | 分别测空格 / 媒体键 / 退出 App | 至少一条可靠，确定兜底链顺序 |
| **6** | 锁屏与暂停顺序 | 先暂停 → `Ctrl+Cmd+Q` → 等 30 秒 | 无声、解锁后仍处暂停 |
| **7** | 客户端窗口标题 / AX 可用性 | AXUIElement 读 `AXTitle`，切集时看是否变化 | 可作 L0 的辅助信号；自绘 UI 可能读不到 |
| **8** | 公证 + library validation | 打进 adapter framework 跑完整公证 | 公证通过、App 能启动 |

> **0 / 1 / 2 是决策点**：0 通过则 v1 精度大幅提升；1 决定 L0 的监听方式；2 决定 MediaRemote 能力是否启用。其余是工程验证。

## 九、验收标准（v1 可发布门槛）

1. 设定 15/30/45/60/90 分钟或自定义时长，倒计时准确，支持「稍后再看 5 分钟」与取消。
2. 「到点立即停止」在腾讯视频官网客户端播放中可稳定暂停，暂停链日志可查；不会误把已暂停的视频重新播起来。
   浏览器渠道靠系统暂停（幂等）覆盖；两个附加动作（退出腾讯视频 / 关标签页）默认关闭，
   **一旦勾选，到点必须执行**，与暂停是否成功、浏览器是否在前台无关。
3. 开启「锁屏」时，**严格先暂停再锁屏**，锁屏后 30 秒无声、解锁后视频仍处暂停。
4. 「播完当前再停」至少能以 L0（事件驱动）或 L3（估算）之一完成，UI 明确标注当前模式，不会静默失败。
5. 首次启动引导辅助功能权限；权限被撤销时有清晰提示而非静默失效。
6. Developer ID 签名 + 公证通过，Mac mini 15.8 上双击可运行，无「无法验证开发者」拦截。
7. Mac Pro 12.x 上同包可启动、基本定时与立即停止可用（不要求 MediaRemote 增强能力）。

---

## 十、给 v2 预留的接口

v1 不要写死「只能控制腾讯视频客户端」，否则 v2 加网页渠道要重写。预留三点：

- `PlaybackSource` 协议：`identifier` / `isPlaying()` / `stop()` / `observeEnd(_:)`，v1 实现 `NativeAppSource`，v2 增加 `BrowserExtensionSource`；
- `StopExecutor` 只接受 `PlaybackSource`，不直接引用客户端 bundle id；
- `PlaybackEndMonitor` 的事件统一为 `PlaybackEnded(reason:)`，v2 由扩展上报 `EPISODE_FINISHED` 走同一条 `executing` 序列。

这样 v2 只需新增扩展 + Native Messaging + 一个 Source 实现，状态机与 UI 完全复用。

## 十一、主要风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 客户端不上报 Now Playing，L0 无法监听 `playing` | 「播完当前」退回 L3 估算 | 用 NSWorkspace 退出事件 + AX 标题变化补；L3 常驻 |
| Spike 0 失败（CDP 被禁用） | v1 无精确进度 | 接受降级，明确产品口径，不承诺精确 |
| Apple 后续安全更新修掉 perl 代理 | adapter 全失效 | 运行时 `test` 自检 + 自动降级；核心功能（立即停止/锁屏）不依赖 MediaRemote |
| 客户端改版导致空格/媒体键失效 | 停止动作失灵 | 五级兜底 + 每级验证 + 用户可手动停止 |
| 锁屏后播放继续 | 核心体验失败 | 强制先暂停；停止后做一次 `playing` 复核再锁屏 |
| 与客户端自带定时功能重复 | 产品价值被质疑 | 定位为「停止方式 + 锁屏联动 + 提醒」，非「定时」 |
